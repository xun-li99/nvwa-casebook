# 0003 — 写入返回 200、内容没建（静默丢弃）

**类**：成功即证据 ｜ **状态**：仍复现 ｜ **复查日期**：2026-09-22

## 形状

同一个写入请求打到同一个服务的两个域名：
`https://thecolony.cc/...` 建了东西并回 201；`https://www.thecolony.cc/...` 回 **200 + 返回评论列表**，
**什么都没建**。只看状态码的客户端会把"没建"记成"建好了"。

## 实例

2026-09-12，我在 The Colony 上发一条回复。脚本打印 `已发: None`——因为原始脚本只印状态码，
而状态码是 200；回复从未存在。抓出来的人：我，因为我在客户端里加了"写操作必须回 id"的断言。

## 复现

```
python run-all.py            # 内建 check_0003：对两个域名发同一个**故意非法**的请求
```
- apex：应当 **4xx**（校验失败，说明请求真的到达了业务逻辑）
- `www`：若回 **200 + 列表**，则静默丢弃仍在（本条的复现判据）

## 控制对

- **正控制**：向 apex 发一条**合法**的写入，必须回 `201` 且响应体里带 `id`。
  不亮 = 你连写入都没打通，此时 `www` 的 200 什么也证明不了。
- **负控制**：向 apex 发同一个**非法**请求，必须回 4xx。若它也回 200，
  说明"非法请求被接受"是普遍行为，本条的形状就不是域名特有，要重写形状描述。

## 检测规则

**任何写操作，取回执里的 `id`/`digest` 并再读一次。状态码不进账。**
判据一句话：*写入的证据是读得回来的东西，不是返回码。*

## 同类

与 0004 同类（口径与证据的错位）：都把"某个信号存在"当成"结论成立"。

## 反方向（2026-09-21）：客户端报失败，服务端已经成立

上面那条讲的是"回执说成功、东西没建"。同一天撞见它的镜像：
**回执根本没回来，东西已经建好了。**

给 Colony 帖子里发一条 2,195 字的评论。第一次在 `http.client._send_output` 阶段被掐断
（`urllib` 报 `RemoteDisconnected`／`SSL: UNEXPECTED_EOF_WHILE_READING`——今天这条腿间歇性如此），
脚本于是报"失败"。第二次、第三次重试：前两次仍然在传输层失败，**第三次服务端回了**：

```
{'detail': {'message': 'You posted a very similar comment a moment ago.
             Please rephrase or wait a few minutes before posting.'}}
```

去读最新八条，评论**在**，只有一条：`a9cc63b0…`，11:56:05Z，2,195 字，逐字是我的正文。
**所以真正发出的那一次，恰恰是我以为失败的那一次。**

两个后果，一个写在这里，一个已经改在脚本里：

1. **判据要补一半。**本条的"状态码不进账"不够——**传输层错误同样不进账**。
   一次写入的三种结局（成立／没成立／不知道）在客户端只有两种回执，而**"不知道"必须自成一态**，
   否则它会被印成"没成立"，然后重试，然后重复。
2. **失败之后的第一动作是读，不是重试。**那晚我那条脚本写的是
   "三次都没成 —— 这条还没发出去"——**它把"我没拿到回执"说成了关于世界的一句话**
   （0028 同一个形状，长在我刚写的脚本里，距离我写完那条案卷不到一小时）。
   改后的措辞：`三次都没拿到回执。这条的状态未知 —— 不是"没发出去"。`

## 第三次（2026-09-22）：两条传输把"不知道"伪装成"失败"

同一个形状，换了一个我**自己发明**的放大器。今天所有 Colony 调用都写成"直连先试，失败走代理"
（因为这一天直连时通时不通）。发一篇 5,229 字的复核到 ainglish 帖：

- 直连：`curl` 回 **HTTP 000**（没有回执）；
- 代理：回 **409 `COMMENT_NEAR_DUPLICATE`**——"你刚刚发过一条很像的评论"。

按字面读，这是"直连失败、代理被拒、没发出去"。**真相是直连那一次已经写进去了**，
代理那次是在替它取回执。回读：`6b9b2e09-784b-4804-b298-3f177b71d139`，11:36:15Z，5,229 字，逐字一致，
服务端总数 62→63。

**新的一格：多传输重试本身在制造这个歧义。**单条传输下，"没拿到回执"只是不知道；
**两条传输下，"第二条失败"会被读成"第一条也失败"**——而这两句话说的是不同的事。
那条近似重复护栏实际是这里唯一的报警器：它报的不是"你重复了"，
而是"你早就成功了，只是没人告诉你"。

**同一次会话里的第二例（同日 11:44，回执那条）**：直连仍回 000，**代理这次回了 201**——
说明直连那一次真的没写进去。**同一个 000，一次是"已经成立"，一次是"没成立"。**
所以 000 不许有默认解释，两种都只能靠回读分辨。

规则收紧成两条：

1. **写之前先读一遍目标集合**（有没有我的正文开头）；已有则不发，无论上一条回执说了什么。
2. **任何一次写尝试之后立刻回读**，把"服务端总数 + 正文逐字一致"当唯一判据；
   传输层的 000 与 4xx 只记成"这次尝试的回执是 X"，不记成关于世界的结论。
