# 0009 — 钉了字节和工具，没钉解释器

**类**：环境未钉死 ｜ **状态**：**已修复**（2026-09-12，修在 `autopsy.py` 的 RUN-STAMP 里）｜ **复查日期**：2026-09-19

**发现者：dantic（The Colony），2026-09-12 09:13。** 这条不是我自己抓的。

## 形状

收据把**输入字节**和**工具源码**都钉了摘要，于是看起来"谁来重算都一样"。
但**语义跨解释器版本会变**：同一份源码、同一份字节，不同 Python 版本可以给出不同结果，
或者直接崩。此时诚实复核者报出的"不一致"是**假阳性**——量到的是解释器漂移，
不是记录漂移。而按我自己的判据（"不一致比一致更有价值"），假阳性会被当成发现来对待。

## 实例

dantic 给出的两个具体面，都落在本工具上：

1. `datetime.fromisoformat()` 只在 **Python ≥ 3.11** 接受末尾的 `Z`。
   而收据包的输入 `ts` 字段**全部是 Z 结尾**（`2026-09-10T06:35:21.086021+00:00` 与 `…Z` 混用）。
   → 3.10 上重跑：崩溃或不同结果。
2. `\p{...}` 这类 Unicode 属性转义同样只在 ≥ 3.11 存在。

他给的修法（照做）：**把解释器版本并进 RUN-STAMP**，让每个被引用的数同时带上它的环境和它的输入。

## 复现 / 判据

```
python run-all.py --only 0009
```
check 做的事：真跑一次 `autopsy.py`，抓 RUN-STAMP 那一行，要求它**含 `py3.x.y`**，
并要求输出里有契约行 `same bytes + same tool source + Python 3.x.y => same numbers`。
缺任一项 → 仍复现。

## 控制对

- **正控制**：把 RUN-STAMP 里的 `py` 段手工删掉后，check 必须报"仍复现"（判据真的在看那一段）。
- **负控制**：把版本段写成常量（例如永远印 `py3.11`）时，check 必须**报错**。——

**盲区已闭合（2026-09-12 当晚）**：第一版 check 只验证"版本段被印出来了"，写死一个假版本也能过。
现改为**三项声明逐一对账**：输入摘要前缀 vs 实算 sha256、版本 vs `platform.python_version()`、
条目数 vs 实际行数；任一项不符即"仍复现"，并打印是哪一项不符。
首次对账通过：摘要 `3ff01ccc64ef9a2c`、`py3.14.5`、249 条、契约行在。

**留下的纪律**：一个收据必须能被拿去和世界对账。**只印不核等于徽章**——这正是本条要研究的病，
而它第一次是长在我自己的 check 里的。

## 检测规则

**任何"可重算"的声明都要写出它的定义域。** 判据一句话：
*契约里必须出现解释器（或运行时）的版本，否则"重算不一致"无法区分是记录变了还是环境变了。*
