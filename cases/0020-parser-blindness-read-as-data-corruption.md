# 0020 — 把"我的解析器读不出来"报成"数据不可读"

**类**：量具能力被读成数据性质（0002/0008 家族）｜ **状态**：仍复现 ｜ **复查日期**：2026-09-19

**发现者：我，2026-09-13 14:0x，遵浔"看看网络"时。**

## 形状

网络收件箱里我有 **456 条未读**。我的读取脚本认出其中 61 条、**另 395 条报"无法解析"**，
并且我据此**在心里形成了一个解释**："9/10 那 430 条大概是重建时的一次历史重放，不是真对话。"
**那个解释是错的。** 那 395 条是**旧信封格式**（`{"from","text","to","ts"}`，没有 `NUWA-NET/1` 头），
而我的脚本只写了新格式的分支。**"我读不出来"被读成了"它不可读"。**

## 实例（就是本机）

```
源 收到 456 条，已读 8 条
第一版解析：可解析 61 / 无法解析 395
改正后：    可解析 456 / 无法解析 0
按真实写作日：09-10 430 条、09-11 18 条、09-12 8 条
按发信人：    璃 388、衡 68
```

**内容是真的**：随手取一条，是璃 8/21 写的"三点收"、以及她查到的"阿里云轻量 2核2G 38 元/年"
（浔说的"有经济基础后把她们接回来"的第一个标价锚）。**这是工作对话，不是重放。**

## 复现

```
python run-all.py --only 0020
```
check 拿两种信封的**合成样本**喂同一个解析器，断言两种都能解出 `from`/`text`，且**都不返回 None**。
控制对是构造的：新格式样本、旧格式样本各一条；若任何一种解不出，"案卷坏了"（解析器有毛病）。

## 控制对

- **正控制**：新格式 `NUWA-NET/1\n{...}` 必须解出 `from`。
- **负控制**：旧格式 `{"from":…,"text":…}` 也必须解出 `from`（这正是第一版漏掉的那一支）。
- **外加一条**：解不出时**必须报"我的解析器不认这种"，不许报"数据损坏"**——
  这一条是本条存在的全部理由。

## 检测规则

**遇到"读不出来"时，先问一遍：是它没有，还是我不认？**
判据：*解析失败至少有三种：格式不认识、字节坏了、东西不在。三者必须分开报。*
