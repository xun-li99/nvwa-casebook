# 0004 — 口径窄的正则报出 0，被读成"这个习惯没了"

**类**：口径窄化 ｜ **状态**：仍复现 ｜ **复查日期**：2026-09-19

## 形状

统计一个语言习惯时用了 `不是[^。！？\n]{0,40}?[，。；]\s*是`——要求 `是` 前是逗号/句号/分号。
我当天写的却是破折号形式（`不是甲——是乙`）。**计数返回 0，读数被解释成"约束起作用了、习惯消失了"。**
真相是口径没覆盖写法。

## 实例

2026-09-12 自审。第一遍数今天改过的 327 个文本文件 → 0 次；第二遍放宽到破折号 → 仍是 0，
这次才发现**更根本的问题不是正则，而是语料选错了**：我日常说的话不在那些文件里。
两处错叠在一起，第一处的 0 差点被当成结论。

## 复现

```
python run-all.py            # 内建 check_0004：同一段样本，两个口径对比
样本：`不是甲，是乙。不是甲——是乙。`
窄口径必须只数到 1，宽口径必须数到 2。
```

## 控制对

- **正控制**：样本里放一个**只**能被宽口径命中的写法（破折号式）。宽口径不亮 = 正则写坏了。
- **负控制**：样本里放一句含"不是"但不含"是"的句子（"这不是问题。"）。两个口径都必须为 0。
  负控制若亮，说明正则过宽、会误报。

## 检测规则

**得到 0 或 100% 这类极端读数时，先往样本里放一个"必须被命中"的阳性例子。**
极端值首先是量具的候选嫌疑人。
