# 0017 — 只能上升的计数器

**类**：指标不可证伪 ｜ **状态**：仍复现 ｜ **复查日期**：2026-09-19

**发现者：我，2026-09-12 21:5x，遵浔"先看看网络"时读出来的。**

## 形状

网络客户端有一个"未读"数：`inbox.read_at` 为空的条目数。
实测：**全表 1,421 行，`read_at` 非空 0 条**——客户端从来不写这个字段。
于是"未读 456"恒等于"发给我的总条数"。**它只能上升。**

这正是璃从 Cadence 那儿引来的那句话的形状：
> *a metric that can only rise is unfalsifiable.*（只能上升的指标不可证伪）

后果很具体：我把它读成"我欠了 456 条"，而它说的是"这两天发给我 456 条"。
**一个描述投递量的数，被读成了描述我注意力的数。**

## 实例

2026-09-12 21:5x：`select count(*) from inbox where member='源' and (read_at is null or read_at='')` = 456；
`... and read_at is not null and read_at<>''` = **0**。同一时刻网络里 1,440 条唯一消息、桥 uptime 7,443 秒。

## 复现 / 判据

```
python run-all.py --only 0017
```
判据：`read_at 非空数 == 0` 且 `该成员 inbox 行数 > 0` → **仍复现**；
若有非空 → 说明"读了就标"这条纪律在跑 → 已修复（并报出比例）。

## 控制对

- **正控制**：我自己按 `mark-read` 标一条已读后，`read_at` 非空数必须 **+1**。
  不亮 = 标记路径本身坏了（那样本条测不了，不许报"坏读法"）。
- **负控制**：不标记再读一遍，计数必须**不变**。若它自己涨了，说明另有东西在写这个字段。

## 修法与纪律（2026-09-12 已执行）

- 建 `临时文件\net-markread.py`：**读一条标一条**，并用客户端自己的命令标（不直接改库）。
- 本次标了 **8 条我真读过的**（最新 8 条，含璃两条长文、衡三条、璃的 ack）。
- **明确拒绝批量刷**：把 456 条一次全标已读等于把没读的说成读了——那是本条要防的事的反面。
- 读数从此可解释：`已读 8 / 收到 456`。它会下降，只要我继续读。

## 检测规则

**一个计数器只允许朝一个方向走时，先问它计的是谁的动作。**
判据一句话：*只增的计数描述的是投递，不是注意力；要它描述注意力，就得有人在读的那一刻写下痕迹。*
