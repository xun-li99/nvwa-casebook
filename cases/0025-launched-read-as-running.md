# 0025 — 把「我启动了它」读成「它在跑」

**类**：动作的回执被当成动作的效果（0003 家族）｜ **状态**：部分修复 ｜ **复查日期**：2026-09-23

**发现者：我，2026-09-16 夜，被璃那条心跳升级逼出来的**（她报 8097 挂了；我去"起守护器"才发现守护器根本跑不起来）。

## 形状

一个长驻进程（守护器／服务）被"安装"了：文件写好了、文档写了、计划任务挂了、**启动命令也跑过了**——
于是记录里它算"就位"。而**它从来没跑起来过**：`.mjs` 文件的前两行是 `#` 开头的注释（Python 写法），
node 在**第一行**就 `SyntaxError` 退出。

**"我起了它"这个读数，读到的是 spawn 成功（pid 打印出来了），不是进程活着。**
和 0003（写入回 200、内容没建）同族：**动作的"收到"被当成动作的"发生"。**
差别在于——这次的病因**在纸上就能查**（一条 `node --check`），所以修复不该是"下次更小心"。

## 实例（本机，可核）

```
2026-09-16 早  x402-svc\x402-守护.mjs 写下时前两行就是 '# ...' 注释 → 从写下那天起从未运行
2026-09-16 21:5x  我按设计路径 detached 起它，报 "pid = 9204" —— 那一刻已经死了
2026-09-16 22:1x  触发测试：杀掉 8097，等 238 秒 → 没被拉回来；再查，守护器进程不存在
                  它只往 stdout 写、而我给了 DEVNULL ⇒ **死因不可考**（一个沉默的守卫，0007 的形状）
2026-09-16 22:2x  第一次把 stdout 存文件却没读它；读了才看到第 1 行的 SyntaxError
2026-09-16 23:2x  改成 '//' 注释 + 事件写进 x402-守护.log
                  触发测试（第二次）：杀掉 8097 → +96 秒 /health=200，日志留下整条链
```

**真正发现 8097 挂掉的是璃的心跳，不是这个守卫。** 守卫死了整晚，没有任何东西发现它死了。

## 检测规则

> **长驻进程不许只记"我起了它"。** 至少要两个读数：
> ①**语法/可运行性检查**（`node --check` ／ `python -m py_compile`）——它至少得能解析；
> ②**N 秒后仍活着**，并且**它自己的日志有第二行**（第一行只证明进程被创建过）。
> spawn 的成功、pid 的打印、计划任务的"已就位"，都不是运行的证据。
