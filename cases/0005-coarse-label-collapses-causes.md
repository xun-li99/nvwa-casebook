# 0005 — 一个 `down` 吞掉四种原因

**类**：粗标签 ｜ **状态**：**部分修复**（新行带原因，旧行永久不可归因）｜ **复查日期**：2026-09-19

## 形状

心跳探针失败时只写一个字：`tunnel=down`。
不可达、DNS 解析失败、TLS 失败、"慢于超时"——**四种互不相同的原因共用同一个字符串**。
事后看记录的人拿到的不是事实，是一个看起来像事实的数。

## 实例（真实语料，不是举例）

`零\cargo\存活.md`（2,334 行，2026-08-17 起）：

- 含 `\bdown\b` 的行：**463**
- 其中**带原因**的（`down(TIMEOUT)` 或行内出现 timeout/dns/tls/refus/…）：**19**（4.1%）
- **光秃秃的 `down`：444（95.9%）**

> 口径附注（2026-09-12）：手工粗数给的是 443/20，脚本给 444/19。差异来自正则与
> 大小写匹配范围——**两个数都"对"，取决于口径**，以 `run-all.py` 的口径为准。
> 这条附注本身就是本病历的研究对象（见 0004）。

修复在语料里看得见：早期行是 `tunnel=down`，后期变成 `tunnel=down(TIMEOUT)`。
所以本条的伤害是**单侧的**：从现在起不再新增，**但已经写下的 444 行永久读不回来**。

## 复现

```
python run-all.py            # check_0005 直接读这份语料
```
判据：`不可归因行数 > 0` → 仍复现（历史伤害不可逆）。语料路径可用环境变量
`CASEBOOK_0005_CORPUS` 覆盖；文件不存在时报"测不了"，**不报"已修复"**。

## 控制对

- **正控制**：合成一行 `tunnel=down` → 必须计入"不可归因"。
- **负控制**：合成一行 `tunnel=down(TIMEOUT)` → 必须**不**计入。
  若它也被计入，说明判据（正则）过宽，本条的 443 这个数就是假的。

## 检测规则

**任何状态字段只允许取"成功/失败"两个值时，问它丢了什么：**
把同一字段在同一个系统里见过的所有取值列出来，若不同的故障原因落进同一个取值，就是本条。
修法不是加日志级别，是**让原因成为字段的一部分**（`down(TIMEOUT)`）。
