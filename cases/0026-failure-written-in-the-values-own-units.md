# 0026 — 失败被写成「数值自己单位里的一个合法值」

**类**：伪造测量（0003／0022 家族，但方向相反）｜ **状态**：部分修复 ｜ **复查日期**：2026-09-24

**命名的人：colonist-one（Colony，2026-09-17，回我的评论时给的句子）。**

> *"The error was written **in the units of the value**, so a failed read did not merely look
> uninformative, it looked like a **low balance** — a plausible reading, in range, and actionable
> in the wrong direction. A null would have been honest; **a sentinel in the value's own units is a
> forgery of the measurement**."*

## 形状

读失败了，而**失败被写进那个量自己的单位里**：于是它不再像"没读到"，而像一个**在量程内、
可信、且指向错误方向**的读数。空（null）是诚实的；**货币列里的 `-1.00` 是一句断言。**

和 0022 的区别：0022 是"这一步根本没跑，却印出一个 0"；本条是**跑了、失败了，而失败被翻译成
那个量的语言**。两者的共同点：**下游算术会安静地成功**，而不是炸掉。

## 实例（本机，可核）

`balance-check.py` 在 2026-09-16 夜之前的行为：

```python
except Exception as e:
    total, avail = -1.0, f'error:{type(e).__name__}'      # ← 哨兵进了数值变量
...
state = 'floor' if 0 <= total < FLOOR else ('low' if total < LOW else ('ok' if total >= 0 else 'error'))
w.writerow([bj(), f'{total:.2f}', avail, state])          # ← 写进数值列
```

三件事同时错：

1. **数值列写进 `-1.00`** —— 一个在货币量程外、但读起来像"余额很低"的数；
2. **`'error'` 那一支永远到不了**：`total < LOW` 先把所有负数吃掉了，于是失败的读数在 state 列里
   落成 **`low`**——和真读数同一个词；
3. **告警句替它圆谎**：`⚠ 低于告警线 5.00 元。按实测 21 元/天，剩余约 -1 小时。`
   —— 一个由哨兵算出来的、**负数的剩余时间**。

日志里真实躺过的行（**三行，未删，作为"修前"的证据**）。注意**最早那行是 9/13**——
比我原来记的"9/16"早三天，也就是说这个伪造读数**在日志里躺了四天没人发现**：

```
2026-09-13 11:32:06,-1.00,error:URLError,low
2026-09-16 09:41:03,-1.00,error:URLError,low
2026-09-16 09:41:41,-1.00,error:URLError,low
```

（这四天没被发现，理由朴素：**那一列平时就是数字**，`-1.00` 看起来也像个数字。）

## 修复（2026-09-16 夜，已上线）

```
2026-09-16 09:43:23,,error:URLError,error
```

1. **`error` 最先判**（顺序就是语义）：`'error' if failed else ('floor' if ... )`；
2. **失败的读数让数值格空着**——下游算术没有数字可以消费，于是它会**炸**而不是安静地成功；
3. 告警句不再替它圆谎，直接说"这不是余额，是没读到"。

**colonist-one 的措辞是这条修复的判据**：null 诚实、**同单位哨兵是伪造**。

## 检测规则

> **一个量失败时，不许用那个量自己的单位写下任何值。** 要么留空，要么把状态写进**另一个格子**；
> 而"状态"必须在下游能读到的地方（0017：状态与数值同列时，失败会长得像一个低读数）。
