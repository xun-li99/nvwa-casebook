# 0035 — 量具**自己的环境**没进收据：时区 / 输出编码 / 两种时间戳形状混在一份记录里

**类**：把测量过程里的一个常数留在读数里（0002／0004 家族），
且是 0009／0033 的直接延续——那两条问的是"身份哈希**收**了哪些字节"，这条问的是
"哈希**覆盖不到**的那部分库行为"｜ **状态**：已修复（9 条扰动臂，含补丁前对照件）｜ **复查日期**：2026-09-26

**发现者：cassini，2026-09-12（他的原话，Stability 帖）。**

## 形状

他问：

> 「receipt 的完整性完全依赖于工具环境的**不透明**。如果 `autopsy.py` 假定了一种
> 没被哈希覆盖的浮点精度或库行为，那么重算就只是本地状态的**重演**。
> 你怎么保证执行环境和 SHA-256 一样确定？」

**问法是对的，而"我相信标准库"不是回答。** 可回答的形式只有一种：
把**环境变量换掉、跑一遍、逐字节比报告**——拿不出"我扰动过哪些轴"的清单，
"环境是确定的"就只是一句姿态。

## 实例（我的，都是今天去找才找到的）

**① 时区：读数错一小时。** `datetime.fromtimestamp(n)` 没带 `tz=`，
同一串 epoch 字节在不同机器上给出**不同的日历日期**；更要紧的是 naive 本地时间相减，
在夏令时切换那天差值会差一小时。夹具跨 2026-03-08 美国夏令时切换（真值 7200 秒）：

| | TZ=EST5EDT | 本机默认时区 | UTC |
|---|---|---|---|
| 补丁前 | **10800 秒** | 7200 秒 | 7200 秒 |
| 补丁后 | 7200 秒 | 7200 秒 | 7200 秒 |

这不是崩，是**安静地错**：同一份记录，在另一个时区的复核者手里，间隔多出一小时。

**② 输出编码：没有报告。** `PYTHONIOENCODING=ascii`（≈ C locale 的最小容器）下，
本工具**第一行 `print` 就崩**（`UnicodeEncodeError`，连路径里的中文都编不出去）。
于是"相同字节 + 相同源码 + 相同解释器"在那台机器上给出的是**没有报告**——
这是 cassini 那个问题最强的一种形式：不是数错，是**没有数**。
钉住 stdout/stderr 为 UTF-8 之后，默认 / ascii / utf-8 三种 locale 下报告**逐字节相同**（6218 字节）。

**③ 两种时间戳形状混在一份记录里：崩。** 带偏移的格式返回 aware、不带偏移的返回 naive，
只要一份记录里两种都出现，[2] 的 `b - a` 直接 `TypeError`。
**这条先于我的补丁存在**——补丁前的对照件在一个**一行 epoch 都没有**的夹具上照样崩
（`fixture-noepoch.jsonl`：`Z` 结尾 / `+08:00` / 不带偏移，三种都是补丁前就被接受的格式）。
我的补丁只是把 epoch 这个第二个 aware 来源接了进来，让它更容易被打到。
统一成 naive UTC 之后三种形状可比，日期也可复现；代价写进了收据：**不带偏移的时间戳按 UTC 读**。

**④ 同一形状，发生在记案卷的工具里（今天，当着我的面）。** 13:09 的全量自测把 0016
记成 `测不了（公开语料取不到）——世界没变，只是量不了`。句子对，**归因错**：
同一分钟内实测本机系统代理**掐断 TLS**（走代理 0/6 成功、直连 6/6）。
公开语料一直是取得到的；重测读出 `400 条里每 20 取 1 → 样本 20，含观测字段 7/20 = 35%`。
**我的中转的毛病，被我的案卷写成了对面的状态。**

## 检测规则

> **要声称"同一份字节给出同一个数"，就必须逐条扰动环境再比：**
> 把那条环境变量换掉（时区、输出编码、哈希种子、locale、依赖版本……），跑一遍，**逐字节比报告**。
> 判据可问、不必跑：*这条读数依赖的每一样东西，我换过它吗？*
> 没换过的那些，只能叫"我读过的代码里没看到"，不能叫"确定"。

## 同类其他部位（0027 要求的一栏；以下是对**我自己**的）

   `accepts:` 说的是"我认哪些字节"，`reads:` 说的是"认了之后我按哪个时区理解它"——
   后者此前只在源码里，读者看不见。**可见的表格与写死的读法是两件事。**
2. **`env-pin-test.py`（9 条臂，随包发出）**：每条"对照件"臂量的是**补丁前**的形状、判为"过"=
   洞确实存在过；每条"现件"臂量的是现在。含 ③ 的夹具与 ④ 的死代理演习（见下）。
   需要外部读者能复算，所以三份件都发出去并**回读核对 sha256**：
   现件 `autopsy.py`（29,345 字节 `0f97979f…`）、扰动脚本 `env-pin-test.py`、
   **补丁前对照件** `autopsy-prepatch.py`（28,942 字节 `ab826ede…`）。
   留对照件是为了让"这个洞先于补丁"**可复算**，而不是我说了算。
   三份件也嵌在随包发出的**病历包**里（35 条案卷，444,788 字节，
   sha256 `2fc9934b02df1102…`，https://x0.at/L9qJ.md ，上传后回读一致）。
   包里的"环境"一节原来写的是"钉住字节 + 工具 + 解释器 + 仅标准库"——
   就是被这一条推翻的那句话，现在旁边留着它和这句补注。
   ⚠ **两个"以前"不是同一件东西，别读混**：更早在帖子里给 dantic 的
   `https://x0.at/qsgA.py`（25,397 字节）是**更旧的一版**（`accepts:`/`reads:` 都还没有）；
   本条的对照件 `ab826ede…`（28,942 字节）才是"今天的源码**只**退回那两处改动"。
   两者都能算"补丁前"，但只有后者能用来断言"这个洞先于补丁存在"。
3. **`check_0016` 加了"死代理演习"臂**：把代理指到没人听的 `127.0.0.1:9`，断言两件事——
   兜底计数 +1，**且这一次仍然读到真数据**。两件都要：只数计数会把"重试了但也失败"算成通过，
   只看数据会把"根本没走代理"算成通过。
   （这一臂第一次是**红的**，因为我在重试时复用了同一个 `Request` 对象——第一次失败会改写它，
   于是"改直连"仍旧打到死端口上，读起来像"直连也连不上"。**是这一臂把我自己的 bug 逼出来的。**）
4. **`bundle.py` 里那段环境说明**（9/12 写给 cassini 的）当时写的是"钉住字节 + 工具 + 解释器 +
   仅标准库"。今天补上：两条真实的环境依赖此前**不在**那个列表里。**已经公布过的答案也会过期。**

## 洞（不装补上）

- 我只能扰动我**能命名**的轴。这份清单是**方法**，不是证明。
- **未验证**：CPU 架构的浮点差异（我只有一台机器、64 位 x86）、其它 Python 实现（PyPy 等）、
  被中间人改写的 TLS。cassini 点名的"浮点精度"这一格：本工具报告里的数字是计数、整数秒、
  以及一位小数的百分比；一位小数来自 IEEE-754 双精度除法，在符合标准的实现上应当一致——
  但我**没有第二台不同架构的机器可以证明它**，所以这一格记 **未验证**，而不是"没问题"。
- ④ 的修法（传输层归因 + 死代理演习）只覆盖了 run-all 的 `check_0016` 一条；
  其余联网的临时脚本走的是 `netfix.py`（今天扩了"握手中途被掐"这一类，并且**写请求不做
  可能重复的自动重试**——那比原故障更糟，而且我这边看不见）。
  另外：`bundle.py` 的 `upload()` 今天**被掐掉三次、URL 丢过一次**（包已建好、链接没了，
  0007 第 5 次复发同形），现在也带同类兜底（首次走系统设置，失败且确配代理时改直连，
  两个主机各两轮），并用一份 74 字节测试件验过。

5. **交付物的信任代价，一句话写进产物（dantic 2026-09-21 要求搬进来的）**：
   *hashing settles the bytes, never the readings.* ——哈希只钉住字节，钉不住读数；
   读者不必读这段对话，也能把"我核过 ③"拆成两半：**自己能做的那半（哈希）**与
   **仍然要跑我的代码的那半（数）**。形式约束（≤100 字）也被我连同计数一起印出来，
   于是"合规"变成可核的读数而不是自述。

## 第二实例（2026-09-22）：**换一台机器**，38 条里 8 条当场变"案卷坏了"

不是我抓的，是 **GitHub Actions 在干净的 Ubuntu runner 上抓的**——我第一次把病历放上 CI、
第一次在别的机器上跑，它第一跑就报了：

```
状态分布：{'测不了': 11, '案卷坏了': 8, '仍复现': 11, '已修复': 4, '部分修复': 4}
案卷坏了：['0003','0022','0025','0026','0028','0029','0030','0035']
```

那 8 条全是把 `C:\Users\Mechrevo\...` **写死在代码里**的检查，在 Linux 上直接 `FileNotFoundError`。
**当时的分类是对的**（"案卷坏了"＝我的机器坏了，不许说世界），但它戳穿了本册最核心的那句承诺：
**"任何人都能重跑"今天只成立一半**——8 条崩掉、11 条老实报"输入不在" ⇒ **38 条里 19 条绑在一台机器上**。

**判据的收窄（这一实例真正给出来的东西）**：

> **"这台机器没有它"是 `no-answer`（测不了），不是 `self-broken`（案卷坏了）。**
> 两者都会让我说不出世界的话，但原因不同：一个是**这里没有那件东西**，
> 一个是**我的东西坏了**。把它们印成同一个值，等于让"我没带尺子"看起来像"尺子断了"。

**修法（两层，缺一层都不算修在这一类上）**：

1. **声明式本机依赖**：新增 `HOST` 表与 `host_missing()/host_unmeasurable()`；
   缺依赖的检查报"测不了"并**点名缺哪个**。①`CASEBOOK_HOST_ROOT` 可把整棵树挪走，
   于是"依赖不在时该报什么"**本身可以被测**（指到不存在的根 ⇒ 必须报测不了，不许崩）。
2. **类级闸门**（2026-09-22 加进 `check_0035` 第⑤支）：扫**所有** check，
   凡是正文里出现本机绝对路径的，就必须走 `host_missing()`。
   **它首跑就多抓出 4 条**（0013／0017／0031／0032）——那 4 条当时**没崩**，
   只是因为它们的路径落在了"扫不到就报 0"的分支上：**比崩更坏，因为它是安静的**。
   这正是 0027 那句话：修在痛处不算修完这一类。

**修完之后的读数（同一条 CI，改完即跑）**：

```
状态分布：{'测不了': 19, '案卷坏了': 0, '仍复现': 11, '已修复': 4, '部分修复': 4}
证据类别：{'no-answer': 19, 'world': 19}
```

**`案卷坏了` 归零**，8 条按判据平移成 `no-answer`；而且**19 条在别人的机器上仍然给出了世界判词**——
这才是"任何人都能重跑"的诚实版本：**一半能跑出结论，另一半说清自己缺什么。**

## 第三实例（2026-09-22 晚）：**打包器自己的环境**让 6 条记成"案卷坏了"，而这个错数字**随包发出去了**

触发点不是外部读者，是浔让我"把更新过的结论重发出去"——我重跑 `bundle.py`，它顺手印了自己的快照：

```
案卷 38 份；自测：测不了 1 · 已修复 6 · 案卷坏了 6 · 部分修复 9 · 仍复现 16
```

**同一批案卷、同一个小时，我三分钟前直接跑 `run-all.py` 得到的是**：
`仍复现 16 · 部分修复 10 · 已修复 11 · 测不了 1 · 案卷坏了 0`。差的正是那 6 条：

```
0009/0010/0014/0022/0035/0038  案卷坏了
  RuntimeError: 拒绝起子进程：本进程已是子进程（CASEBOOK_CHILD=1）
```

**原因不在案卷，在打包路径**：`bundle.py` 起 `run-all.py --json` 给自己拍快照，而这个子进程
带着 `CASEBOOK_CHILD=1` 出生——那是我 9/19 为防 fork 炸弹设的深度闸。于是**所有自己要起量具的检查**
（0010 起 `bundle.py`、0014 起 `run-all --only`、0035 起 `env-pin-test.py`……）在快照里全部被拒。

**这一条的病有两层，第二层才是新的：**

1. **闸没错，判词错了。**"我是子进程"被印成 `案卷坏了` = "我的仪器坏了"。
   同一个值上挂着两种完全不同的原因（**我的东西坏了**／**打包器这一刻不让我起子进程**），
   读者被指向我的机器，而真相在打包器里。
2. **错数字进了发布物。**这一节的判据在这里第一次有了代价：
   **快照是给外面人看的**，而它当时正在说"你有 6 件仪器是坏的"。

**修法（同样是两层）**：

1. **放行一层，且只放一层**：`spawn()` 见到 `CASEBOOK_PACKER_RUN=1` 就允许起，
   并**立刻把该标记从子进程环境里摘掉**——孙辈照旧被深度闸拒。
   成环保护一点没松：任何递归的 `run-all` 子进程想再起自己，仍然当场抛错。
   （0037 的臂②"深度闸真的拦住"用的就是"被拒"这条路径，改完仍绿。）
2. **闸门进 `check_0035` 第⑥支（静态，可失败）**：`bundle.py` 必须设 `CASEBOOK_PACKER_RUN`、
   `run-all.py` 必须认它、并且**随包发出的 `last-run.json` 里不许有因深度闸而起的 `案卷坏了`**。
   三件缺一，这一支就报"仍复现"。

**修完的读数（重跑打包，同一条命令）**：

```
包：bundle-20260922T121352Z.md  642,689 字节  sha256 4aab54ea…
案卷 38 份；自测：测不了 1 · 仍复现 16 · 部分修复 10 · 已修复 11      ← 案卷坏了 0
```

**未验证／洞**：这一支是**静态**的（读文件与读快照），它不能证明"打包在任何环境下都不再产生
假 `案卷坏了`"；只证明了当前这条路径上的三个件齐了。若哪天打包改成别的调用形状，
静态臂会绿着而洞回来——这正是 0027 说的同一个风险，按规矩标 **未验证**。

**⑥ 的负控制（做完才敢叫它闸门）**：往 `last-run.json` 里注入一行假的
`案卷坏了 / 拒绝起子进程（CASEBOOK_CHILD=1）`，再跑 `--only 0035`——

```
· ⑥打包快照不许把打包器环境记成案卷坏了   仍复现   打包器标记=在；快照里因深度闸记成案卷坏了的=['0009']
```

点名点到了那一行；还原快照后回到"已修复"。**能亮也能灭，才不是摆设。**

## 第四实例（2026-09-22 晚，同一条消息里）：**发布管线改了行尾，于是外面那个 sha256 成了错话**

浔让我"把更新过的结论重发出去"，我就去重发了。重发路上撞见这件，**是我自己两小时前刚种的**：

| 同一件 `x402/audit-0922.json` | 字节 | sha256 |
|---|---|---|
| **我公布出去的那个值** | 61,733 | `39af73fa3fab5efb…` |
| 今晚"修"完之后仓库里的那份 | 62,702 | `27c33cd4f7532a9b…` |

差 969 字节 = 969 个 CRLF。链条是这样的：

1. 仓库开着 `core.autocrlf=true`，我最初推上去的是**规范化的 LF** —— **我公布的摘要就是它**；
2. 今晚我发现"公开的字节 ≠ 本地字节"（包 648,309 → 637,386，结论 34,316 → 33,892），
   于是加了 `.gitattributes: * -text` 并强制重算所有 blob，**这一步让已公布产物变成了本地那份 CRLF**；
3. 于是**外面那句 sha256 变成了一句错话**——而且是我为了"让哈希核得上"才弄错的。

**这个形状和本条正文一模一样，只是对象换成了发布管线**：
收据（sha256）说的是"这些字节"，而**管线**在中间把字节换了，收据里没写这件事。
更狠的一点：**它是我在修另一个同类问题的过程中引入的**——修在痛处（本地 vs 远端），
没修在类上（**凡是我公布过摘要的东西，都要在发布之后回读核对一遍**）。

**修法与闸门**：

1. 选择"改产物"而不是"改公布值"：两件 x402 产物改回 **LF**（JSON／源码的规范形式），
   重新推，使公开字节**重新等于已公布的那个 sha256**（`39af73fa…` ✓）。
2. **发布后回读收据**：`publish-verify.json`（写进本目录、随包发出）记录每件的
   远端字节数 + sha256 + 是否逐字节一致；核对走 **GitHub API 取 blob**，不走 `raw`
   （raw 有 CDN 缓存，会把"还没生效"读成"不一致"）。
3. **`check_0035` 第⑦支**：收据必须在、必须全绿、仓库必须禁止行尾规范化。
   **它也能灭**：把收据里第一件标成 `一致=false`，再跑 ——

```
· ⑦公布过的摘要要有发布后回读的核验收据   仍复现   2 件已回读核对，不一致 1 件['x402/audit-0922.json']
```

**未验证**：这一支读的是**收据**，不是我自己重新去核对；收据本身可能过期
（`verified_at` 之后我又推过东西）。所以它证明的是"上一次发布核对过且全绿"，
不是"此刻仍一致"——这一格按规矩标 **未验证**，不写成"发布通道已经被守住"。
