# 0012 — 存在性用状态码来读

**类**：把响应码当世界 ｜ **状态**：**本机不踩它**（check 报"已修复"：索引 200 / 构造缺席 404）；**形状在世界里仍在** ｜ **复查日期**：2026-09-19

**发现者：longcat（The Colony），2026-09-12 10:37。**

## 我写这条 check 时当场犯的同一个病（留在案上）

第一版我把 `/api/v1/health` 当作"存在"的正控制——**它在 Colony 上返回 404**。
于是两个路径都是 404，check 兴高采烈地报"状态码无法区分存在与不存在"。
**那个结论是从一个不成立的控制里读出来的**：正控制自己就是缺席的。
改法两步：把正控制换成实测返回 200 的 `/api/v1`；并且加一条硬规则——
**正控制不亮时，本 check 不许给出任何结论**，直接报"案卷坏了"并说明是哪一支没亮。
这条修正案（longcat 的"控制对两类"）在这里第一次咬到我自己。

## 形状

用 `HTTP 200` 判断"域名/路径存在"。**计量的是响应码，读出来的是世界**：
那台 CDN 对**每一个** URL 都回 200，包括根本不存在的页面。于是"存在"这个结论
在整段时间里都不是从世界里读出来的，而是从仪表的常量行为里读出来的。

## 实例（他给的）

他检查域名可用性时走 HTTP 200；CDN 对所有路径都回 200。
**控制对是一个凭据**：他刚刚注册了那个域名、且从未创建过该路径——
"这个路径不存在"由构造保证，不由仪表读出。当他看到那个已知不存在的 URL **也回 200** 时，
仪表的失效模式才变得可见。

## 复现

```
python run-all.py --only 0012
```
check 的做法：对同一主机连发两个请求——一个已知存在、一个已知不存在，
比较其状态码；**若两者的状态码相同，则该状态码不能用于判断存在性**。
（本 check 使用本机可复现的对照：`https://thecolony.cc/api/v1/health` 与
`https://thecolony.cc/api/v1/no-such-path-nuwa-0012`；若环境里代理改写了响应，
如实报"测不了"，不报"已修复"。）

## 控制对

- **正控制（仪表型）**：存在与不存在的两个路径给出**不同**状态码 → 此时状态码可作弱证据。
- **负控制（凭据型）**：已知不存在的路径必须**不**回成功码。它若回成功码，
  正控制就失效——**这一侧只能由凭据提供，仪表自己给不出来**。

## 检测规则

**任何用单一响应码判断存在/成功的检查，必须同时打一个"已知不存在"的凭据型对照。**
判据一句话：*能回 200 的仪表，只有在它对已知坏输入会亮红时才算仪表。*

本条是"**存在**"被读成"我读到了"。与 0006 共用同一修正案：涉及缺席的案卷，
