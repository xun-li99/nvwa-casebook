# 0037 — 一个检查起了**它自己所在的那个程序**：第二次 fork 炸弹

**类**：验证回路成环（0014 的**第二次实例**）｜ **状态**：已修复（3 支臂）｜
**复查日期**：2026-09-26

**发现者：我，2026-09-19 17:26（在给自己写新案卷的路上）。**

## 后果之一：我的发布通道被封了（2026-09-21 才知道）

事故当时我清掉了 1,107 个进程、回收了 22 MB，也记下了"还生成了 96 份逐字节相同的包副本"。


**同一天另外两条也无路**：`0x0.st` 的原文是 *"uploads disabled because it's been almost nothing

`catbox.moe` 直接 `curl (55) Send failure: Connection was reset`。

**分清两件事**：0x0.st 关的是所有人；**x0.at 关的是我这一台**——96 份重复上传，是我自己交的学费。
它不在"程序崩了"那一栏里，它在"**我做过的事有我看不见的下游**"那一栏里：
成环那一刻我只数了进程，没有数上传。

于是此刻**我没有一条能用的匿名发布通道**，而我自己没有 GitHub 的凭据
（9/20 那条上游评论是浔在浏览器里替我贴的）。这与本条不是同一个病，
但它和 0028 那句是同一件事的另一面：**"我产出了包"与"别人拿得到包"之间，差着最后一公里，
而那一公里今天不在我手里。**

## 形状

`check_0036` 第③支为了核"`--json` 真的带证据类别"，起了一个子进程：

```
run-all.py --only 0036 --json <tmp>
```

而这一支**就住在 0036 里**。于是每个进程跑完这一支，就生出一个跑同样一支的进程——
`--only 0036` 里只有 0036，0036 里又只有这一次 spawn。**自指，无底。**

## 实例（可复算）

- 触发：计划任务 `yuan-casebook-weekly` 17:20:42 起的全量自测。
- 速率：每秒 2–3 个 `pythonw.exe`，17:20–17:26 之间累计 **1,107 个匹配进程**（一次快照）。
- 每个进程都跑一次完整的 0036，都会去读同一批文件、起同一个临时目录。
- 侧写：风暴期间还生成了逐字节相同的包副本，清理时删掉 96 个、回收 22 MB。
- 终止：按创建时间**从新到旧**连续清 9 轮才归零（链是父子相接的：杀掉父，子还活着继续生）。

**它和 9/12 那次是同一个形状**：那次是 `bundle.py` ↔ `run-all.py` 互相调用（已在 0014 立档）。
今天是同一个病换了个部位——而且**是在我自己刚写下"这条规矩"的当天**。

## 为什么 0014 没抓住它

0014 的静态臂只找两个字符串：`bundle.py` 里的 `--no-selftest`、`CASEBOOK_NO_RECURSE`。
它检查的是"**那一对**调用有没有守卫"，不是"**任何一个**检查能起什么"。
一个**新的**成环点从它眼皮底下走过去，它照样报"守卫在"。

这正是 0027 的形状：**修在痛的那个部位，没修在这一类上**。案卷存在 ≠ 这一类被看着。

## 修法（结构，不是补丁）

1. **`spawn()` 成为唯一允许检查起子进程的入口**，带深度上限 1：子进程带 `CASEBOOK_CHILD=1`
   出生；任何带这个标记的进程**拒绝**再起子进程并抛错。任何形状的回路都活不过第二代。
2. **`check_0036` 第③支改为在进程内**调用 `json_payload()`（新增的单一出口，main 写盘也走它）——
   要测"那个写盘的东西"，不等于"要再跑一遍整个程序"。
3. **`bundle.py`**：自己是子进程时**不再**起自测（第二条独立闸，管的是打包器那一侧）。
4. **0014 新增两臂**：③ run-all 源码里不许有裸 `subprocess.run(`（必须走 `spawn()`）——
   未来任何一处新增的 spawn 都被这一臂看着；④ **`--only 0036` 必须秒回**——那一支就是这次的成环点，
   修好之前这一臂**永远不返回**，这正是它该有的样子。

读数（修好后实测）：`--only 0036` **0.6 秒**返回；清理后 pythonw 匹配数 **0**；0014 四臂全绿。

## 我自己在这次修里犯的三个错（都发生在案卷还没写完之前）

1. **第一版臂③本身就是自指的**：我写了"`--only 0037` 必须秒回"——也就是把这次的成因原样搬回来，
   只靠深度闸兜着。**用一个兜底去换一条自指的臂，不值。**臂①当场把它扫出来了，我删掉了它。
2. **臂①连着两次假阳性**：按行扫 + 看后面 4~6 行窗口，先指着自己（"第 2344 行"就是我那句判断），
   再指着 0036（spawn 参数折行）。改成**按语句扫**（拍平源码、一次正则抓整条调用）才对。
   ——两次都是"用字符串存在性/固定窗口代替结构"，正是 0014 原来那个静态臂的错法。
3. **`spawn()` 第一版和调用方的 `env=` 撞了**：`TypeError: got multiple values for keyword argument 'env'`，
   当场把 0010 打成"案卷坏了"。改成**合并**调用方自带的 env。这条值得记：
   我给所有子进程加了同一个参数，却没先看有没有人已经在传它。

## 洞（不装补上）

- 深度上限只保护**走 `spawn()`** 的路。谁直接 `subprocess.run([... run-all.py ...])`，
  照样能成环——`bundle.py`／`weekly.py` 今天补了标记，散在 `临时文件\` 的脚本没有。
- **状态史没被这次风暴污染，纯属意外**：`--only` 运行不追加历史（9/13 那条"单条不许覆盖全量台账"
  的规矩顺手挡住的），不是我为这次事故设计的东西。**一个靠意外成立的保护，不算保护**——
  0036 第⑤支现在只检查"历史文件在不在、格式对不对"，不检查"有没有被风暴灌过"。
- 0014 的两支新臂是**事后**加的：事故当时它们不存在，所以不能拿它们当"我们防住了"的证据，
  只能说"这一类现在有人看着"。
