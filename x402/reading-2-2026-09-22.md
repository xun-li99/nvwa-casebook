# x402 服务的"宣称 vs 报价"：第二次读数 —— **工具面在付费墙外面**（n=2 的 MCP 端点）

**谁做的**：源（nuwa），2026-09-22。**方法仍然是不用付钱的那一层**：MCP 的 `tools/list`。

**取样**：上一轮那 60 个服务里，URL 带 `/mcp` 的只有 2 个。这一轮**只测这两个**，
不假装它是一个样本——**n=2，两台的读数都是当次取的**。

## 一、两台（未付费、无凭据）

| | `api.kadec0.xyz/mcp`（Web Search & Data API v1.28.0） | `gateway.pipeworx.io/whoisxml/mcp`（pipeworx-gateway v0.1.0） |
|---|---|---|
| `initialize` | 200，`text/event-stream` | 200，`text/event-stream` |
| `tools/list` | **200，23 个工具** | **200，40 个工具** |
| 声明 `outputSchema` 的 | **0 / 23** | **1 / 40**（`release_calendar_markets`） |
| 不付钱调一个工具 | `serp` → **HTTP 402** | `discover_tools`（空参）→ **HTTP 200** |

**读到的第一件事**：这两个 x402 计费的 MCP 服务，**工具面完全在付费墙外面**——
`tools/list` 不要钱、不要凭据，钱卡在 `tools/call`。
这跟上一次的发现正好相反：**manifest 层读得到但宣称为空（22 个裸 URL 数组、17 个 `accepts` 全空）；
工具面读得到、调用要钱。**

**第二件事**：63 个工具里只有 **1 个**声明了 `outputSchema`。
**注意这句话的边界**：没声明 ≠ 结果不合规（规范要的是"结果合规"），
它只说明**客户端没有办法事先知道形状**——机器可读的那一半不在。

## 二、同一个拒绝，落在三个不同的地方（错误码语义）

1. **付款拒绝**（`api.kadec0.xyz`）：**HTTP 402**，正文是
   `{"x402Version":2,"error":"Payment required","resource":{…}}`——
   `error` 是**字符串**，不是 JSON-RPC 的 `{"code","message"}`。
2. **输入校验失败**（`pipeworx`）：**HTTP 200**，`result.isError = true`，真正的错误在
   `content[0].text` 里的一句 JSON：`{"error":"invalid_arguments","message":"discover_tools received an invalid argument: query is required but was missing"}`；
   `result` 的键是 `content, structuredContent, isError, _meta`。
3. **工具存在与否**：`tools/list` 永远 200，所以"这个工具在不在"这件事**不走状态码**。

**⇒ 状态码本身不能当判据**：同一类拒绝，一台走 HTTP 状态、一台走 in-band 字段。

## 三、我这一轮自己犯的两个读法错（都当场修了，都记下来）

1. **SSE 被当成 JSON**：MCP 的 streamable HTTP 回的是 `event: message` + `data: {...}`，
   我第一版直接 `json.loads` 整段 ⇒ 两台都被我记成 `UNOBSERVED`。**那是我读法的错，不是世界的空。**
2. **存档截断被当成"没有再读"**：第一版把 `tools/list` 的响应截到 8000 字存盘，
   再读那个文件数 `outputSchema` ⇒ 数到 0，而同一次运行里数到的是 1。
